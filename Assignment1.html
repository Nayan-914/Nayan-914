Database Management System

1. What is Database and DBMS? List out the advantages and disadvantages of DBMS.

A Database is an organized collection of structured data stored electronically in a computer system.

A DBMS (Database Management System) is software that interacts with users, applications, and the database itself to capture and analyze data.

Advantages of DBMS:

  • Data sharing among multiple users
  • Reduced data redundancy
  • Data integrity and security
  • Concurrent access control
  • Backup and recovery features
  • Data independence

Disadvantages of DBMS:

  • High initial setup cost
  • Complexity in design and implementation
  • Performance overhead
  • Need for specialized personnel (DBA)
  • Vulnerability to failures

3. Explain the different models of DBMS with advantages and disadvantages.

1. Hierarchical Model

This model organizes data in a tree-like structure, with parent-child relationships. Each child has only one parent.

  • Advantages:
    • Easy to understand and navigate.
    • Fast access to data in a hierarchical structure.
    • Data integrity is maintained via parent-child relationships.
  • Disadvantages:
    • Complex to modify (insertion/deletion may require restructuring).
    • Cannot handle many-to-many relationships.
    • Data redundancy can be high.

2. Network Model

Similar to the hierarchical model, but allows many-to-many relationships. Uses pointers to connect records.

  • Advantages:
    • Supports complex relationships.
    • Faster data access using pointers.
    • More flexible than hierarchical.
  • Disadvantages:
    • Complex to design and maintain.
    • Difficult for users to understand.
    • Changes in structure are hard to manage.

3. Relational Model

Data is organized in tables (relations). Uses primary keys and foreign keys to establish relationships.

  • Advantages:
    • Easy to use and understand (table format).
    • Strong mathematical foundation.
    • High flexibility and scalability.
    • Supports SQL.
  • Disadvantages:
    • Performance may degrade with very large databases.
    • Complex queries can slow down the system.
    • Not ideal for unstructured data.

4. Object-Oriented Model

Combines the features of object-oriented programming with DBMS. Data is stored as objects, similar to programming languages like Java or C++.

  • Advantages:
    • Ideal for complex data like images, videos, etc.
    • Supports inheritance, encapsulation, and polymorphism.
    • Better for applications with complex relationships.
  • Disadvantages:
    • More difficult to learn and implement.
    • Less mature compared to relational model.
    • Not widely supported.

5. Entity-Relationship (ER) Model

It’s a high-level conceptual model used in the design phase. Data is represented using entities (objects) and relationships.

  • Advantages:
    • Easy to design and visualize.
    • Helps create an accurate database structure.
    • Useful for communication between designers and users.
  • Disadvantages:
    • Not used for actual storage—only for design.
    • Needs to be converted to relational model for implementation.

6. Document / NoSQL Model

Used in NoSQL databases, especially for unstructured or semi-structured data. Data is stored as documents (e.g., JSON, XML).

  • Advantages:
    • Highly flexible and scalable.
    • Ideal for big data and real-time web apps.
    • Schema-less — can store different types of data.
  • Disadvantages:
    • Lacks standardized query language like SQL.
    • Data integrity may not be guaranteed.
    • Complex relationships are harder to manage.

4. What is a relational database? How is it different from other database models?

A relational database organizes data into tables (relations) with rows and columns, where relationships between tables are established using keys.

Differences from other models:

  • Uses tables instead of trees (hierarchical) or graphs (network)
  • Data is stored in a structured format with strict schema
  • Relationships are logical rather than physical pointers
  • Uses SQL for querying
  • Supports ACID properties (Atomicity, Consistency, Isolation, Durability)

5. What is data redundancy?

Data redundancy occurs when the same piece of data is stored in multiple places.

How DBMS reduces redundancy:

  • Normalization process eliminates duplicate data
  • Foreign keys create relationships instead of duplicating data
  • Centralized storage ensures single source of truth
  • Views can present data from multiple tables without storing it redundantly

7. Who is Database Administrator (DBA)? What are the major responsibilities of DBA?

A professional responsible for managing, maintaining, and securing databases.

Major responsibilities:

  • Database design and implementation
  • Performance monitoring and tuning
  • Backup and recovery planning
  • User access management and security
  • Data integrity enforcement
  • Capacity planning
  • Troubleshooting database issues
  • Implementing new database technologies

9. Explain the terms:

h3>

1. Primary Key

Definition:
A primary key is a column (or combination of columns) in a table that uniquely identifies each record in that table.

  • It cannot be NULL.
  • It must be unique for every record.

Example:

CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(100),
    Age INT
);

Students Table Structure:

Column Data Type Key / Constraint Description
StudentID INT Primary Key Uniquely identifies each student
Name VARCHAR(100) – Student’s full name
Age INT – Student’s age

2. Foreign Key

Definition:
A foreign key is a column in one table that refers to the primary key in another table. It is used to establish a relationship between two tables.

Example:

CREATE TABLE Departments (
    DepartmentID INT PRIMARY KEY,
    DepartmentName VARCHAR(100)
);

CREATE TABLE Employees (
    EmployeeID INT PRIMARY KEY,
    Name VARCHAR(100),
    DepartmentID INT,
    FOREIGN KEY (DepartmentID) REFERENCES Departments(DepartmentID)
);

Employees Table Structure:

Column Data Type Key / Constraint Description
EmployeeID INT Primary Key Unique employee identifier
Name VARCHAR(100) – Employee’s full name
DepartmentID INT Foreign Key Links to Departments table

3. Candidate Key

Definition:
A candidate key is any column (or combination of columns) that can uniquely identify a row in a table.

  • There can be multiple candidate keys in a table.
  • One of them is chosen as the primary key; others become alternate keys.

Example:

CREATE TABLE Users (
    UserID INT,
    Email VARCHAR(100),
    Username VARCHAR(50),
    PRIMARY KEY (UserID)
);

Users Table Structure:

Column Data Type Key / Constraint Description
UserID INT Primary Key Unique numeric identifier for each user
Email VARCHAR(100) Unique (Candidate Key) User’s email address
Username VARCHAR(50) Unique (Candidate Key) User’s chosen username

10. What is SQL? Explain its components and common functions.

Structured Query Language (SQL) is the standard language for managing, accessing, and manipulating data in relational databases. With SQL you can:

  • Create databases and tables
  • Insert, update, and delete data
  • Retrieve data using queries
  • Control user access and permissions

Components of SQL

Component Description Key Commands
DDL
(Data Definition Language)		 Defines and modifies the structure of database objects. CREATE, ALTER, DROP, RENAME, TRUNCATE
DML
(Data Manipulation Language)		 Handles data inside tables. SELECT, INSERT, UPDATE, DELETE
DCL
(Data Control Language)		 Controls access to data and permissions. GRANT, REVOKE
TCL
(Transaction Control Language)		 Manages transactions, ensuring data integrity. COMMIT, ROLLBACK, SAVEPOINT

Common SQL Functions

Function Type Purpose Examples
Aggregate Functions Perform calculations on data sets. SUM(), AVG(), COUNT(), MIN(), MAX()
String Functions Manipulate text values. UPPER(), LOWER(), LENGTH(), CONCAT()
Date/Time Functions Work with date and time data. NOW(), CURDATE(), DATEDIFF()
Conversion Functions Convert between data types. CAST(), CONVERT()
Mathematical Functions Perform numeric operations. ROUND(), ABS(), CEIL(), FLOOR()

12. Define the following terms.

a. Data Dictionary

A data dictionary is a file or set of information that describes the structure, meaning, and relationships of data in a database. It acts like a reference guide, listing tables, columns, data types, and constraints.

b. Primary Key

A primary key is a unique identifier for each record in a database table. No two rows can have the same primary key, and it cannot be empty (NULL). Example: An "Employee ID" in an employee table.

c. Relationship

A relationship defines how tables in a database are connected. Common types are:

  • One-to-One (e.g., one person has one passport)
  • One-to-Many (e.g., one customer has many orders)
  • Many-to-Many (e.g., students and courses, where one student takes many courses, and one course has many students)

d. Data Manipulation Language (DML)

DML is a set of SQL commands used to insert, update, delete, and retrieve data from a database. Examples:

  • INSERT (add new data)
  • UPDATE (modify existing data)
  • DELETE (remove data)
  • SELECT (fetch data)

e. Structured Query Language (SQL)

SQL is the standard language used to communicate with databases. It allows users to create, modify, and query data. SQL includes commands for:

  • Defining tables (DDL)
  • Manipulating data (DML)
  • Controlling access (DCL)

f. Data Integrity

Data integrity ensures that data in a database is accurate, consistent, and reliable. It is maintained through rules like:

  • Primary Keys (no duplicates)
  • Foreign Keys (valid references between tables)
  • Constraints (e.g., NOT NULL, UNIQUE)

g. Data Definition Language (DDL)

DDL is a part of SQL used to define and modify database structures. Examples:

  • CREATE (make a new table/database)
  • ALTER (modify an existing table)
  • DROP (delete a table/database)

h. Data Security

Data security refers to protecting a database from unauthorized access, corruption, or theft. Methods include:

  • User authentication (passwords, permissions)
  • Encryption (securing sensitive data)
  • Backups (preventing data loss)

i. Database System

A database system is software that manages and organizes data efficiently. It includes:

  • Database (where data is stored)
  • DBMS (Database Management System) (software like MySQL, Oracle)
  • Users & Applications (interacting with the database)
