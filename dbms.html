Data and Information

Data refers to raw facts and figures, while Information is processed data that is meaningful and useful for decision making.

Features of Information

  • Accuracy: Information should be free from errors
  • Timeliness: Information should be available when needed
  • Relevance: Information should be pertinent to the decision at hand
  • Completeness: Information should contain all necessary details
  • Consistency: Information should be consistent across the organization

Database and its Purpose

A database is an organized collection of data stored and accessed electronically. Its main purposes include:

  • Data organization and storage
  • Efficient data retrieval
  • Data sharing among users and applications
  • Data integrity and security
  • Reduction of data redundancy

Terminologies in Database

Term Definition
Table A collection of related data organized in rows and columns
Field A single piece of information in a table (column)
Record A complete set of fields about one item (row)
Tuple Another term for a record in relational databases
Object In object-oriented databases, an instance of a class
Keys Fields used to identify and establish relationships between tables
Data Dictionary A centralized repository of information about data such as meaning, relationships, origin, usage, and format

Database Management System (DBMS)

Introduction

A DBMS is software that interacts with end users, applications, and the database itself to capture and analyze data.

Objectives

  • Data integration and sharing
  • Data independence (physical and logical)
  • Controlled redundancy
  • Consistency and integrity
  • Security and privacy
  • Backup and recovery

Advantages

  • Improved data sharing
  • Improved data security
  • Better data integration
  • Minimized data inconsistency
  • Improved data access
  • Improved decision making

Disadvantages

  • Increased costs (hardware, software, personnel)
  • Management complexity
  • Maintaining currency
  • Performance issues with large databases
  • Impact of failure (single point of failure)

Types of Database Models

Hierarchical Model

Organizes data in a tree-like structure with parent-child relationships. Each parent can have many children, but each child has only one parent.

Network Model

An extension of hierarchical model allowing many-to-many relationships through a graph structure.

Relational Model

Stores data in tables (relations) with rows and columns. Relationships are maintained through keys.

Entity-Relationship Model

A conceptual model that describes data as entities, attributes, and relationships.

Integrity Constraints and Types

Domain Integrity

Ensures that only valid values are permitted for an attribute (column).

Entity Integrity

Requires that each entity (row) has a unique identifier (primary key) and no part of the primary key can be null.

Referential Integrity

Ensures relationships between tables remain consistent through foreign keys.

Keys

Key Type Description
Primary Key Uniquely identifies each record in a table
Foreign Key Links two tables by referencing the primary key of another table
Candidate Key A column or set of columns that could qualify as a primary key
Super Key A set of columns that uniquely identifies rows but may have extra columns
Composite Key A primary key consisting of multiple columns

Normalization

Introduction

Normalization is the process of organizing data in a database to reduce redundancy and improve data integrity.

Normal Forms

First Normal Form (1NF)

  • Each table cell should contain a single value
  • Each record needs to be unique

Second Normal Form (2NF)

  • Must be in 1NF
  • All non-key attributes are fully dependent on the primary key

Third Normal Form (3NF)

  • Must be in 2NF
  • Has no transitive functional dependencies

Advantages

  • Reduced data redundancy
  • Improved data integrity
  • Better database organization
  • Easier database maintenance

Disadvantages

  • Increased complexity
  • More tables to join in queries
  • Potential performance impact

Centralized and Distributed Database

Introduction

Centralized Database: Data is stored at a single location

Distributed Database: Data is stored across multiple locations connected via network

Advantages of Distributed Database

  • Improved availability and reliability
  • Local control of data
  • Modular growth
  • Faster response for local queries

Disadvantages of Distributed Database

  • Complexity in design and maintenance
  • Higher costs
  • Security challenges
  • Consistency maintenance

Comparison

Factor Centralized Distributed
Data Location Single location Multiple locations
Cost Lower initial cost Higher initial cost
Maintenance Easier More complex
Fault Tolerance Single point of failure More resilient
Performance Good for centralized access Better for distributed access

Database Security

Introduction

Database security refers to the protection of database from unauthorized access, misuse, or destruction.

Challenges

  • Unauthorized access
  • Data corruption
  • Data theft
  • SQL injection
  • Denial of service attacks

Security Measures

  • Authentication and authorization
  • Encryption
  • Auditing
  • Backup and recovery
  • Firewalls
  • Input validation

Roles of Database Administrator (DBA)

  • Database design and implementation
  • Security administration
  • Backup and recovery
  • Performance tuning
  • User management
  • Database maintenance

Practical Topics: DDL and DML Languages

DDL (Data Definition Language)

Used to define and modify database structure:

CREATE TABLE, ALTER TABLE, DROP TABLE, TRUNCATE TABLE, CREATE INDEX, DROP INDEX, CREATE VIEW, DROP VIEW

DML (Data Manipulation Language)

Used to manage data within database objects:

SELECT, INSERT, UPDATE, DELETE, MERGE, CALL, EXPLAIN PLAN, LOCK TABLE
