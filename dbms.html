Data and Information

In database systems, data refers to raw, unprocessed facts and figures that lack meaning on their own. These can be numbers, text, images, or any other form of representation. For example, "25, 30, 22" could represent test scores, temperatures, or ages without any context.

Information is processed data that becomes meaningful when organized, structured, or analyzed. Using our previous example, if we calculate that the average of those numbers is "25.6", it transforms into useful information that can help in decision-making.

Key Differences:

  • Data: Raw and unorganized (e.g., a list of customer names)
  • Information: Processed and meaningful (e.g., "Customer X made 5 purchases totaling $500")

Features of Good Information:

  • Accuracy: Must be correct and reliable
  • Timeliness: Available when needed
  • Relevance: Applicable to the current situation
  • Completeness: Contains all necessary details
  • Understandability: Clear and easy to interpret

Database and Its Purpose

A database is an organized collection of related data stored electronically. Think of it like a digital filing cabinet where information is systematically arranged for quick retrieval and management.

Why We Use Databases:

  • Efficient Storage: Handles large amounts of data systematically
  • Quick Access: Finds information in milliseconds
  • Reduced Redundancy: Minimizes duplicate data
  • Data Integrity: Maintains accuracy and consistency
  • Security: Protects sensitive information
  • Multi-user Support: Allows simultaneous access

For example, a school database might store student records, course information, and grades - all organized and linked together for easy management.

Database Management System (DBMS)

A DBMS is software that acts as an interface between users and databases. It's like the control center that manages how data is stored, organized, and retrieved.

Key Objectives:

  • Provide efficient data storage and retrieval
  • Maintain data accuracy and security
  • Reduce data duplication
  • Support multiple users working simultaneously

Advantages:

  • Better data organization and less redundancy
  • Powerful querying with languages like SQL
  • Strong security controls
  • Backup and recovery features

Disadvantages:

  • Can be expensive to implement
  • Requires trained database administrators
  • Potential performance issues with complex systems

Popular DBMS examples include MySQL, Oracle, and Microsoft SQL Server.

Normalization is the process of organizing data in a database to reduce redundancy and improve data integrity.

Forms:

  • 1NF (First Normal Form): Atomic values, no repeating groups.
  • 2NF (Second Normal Form): 1NF + no partial dependency on primary key.
  • 3NF (Third Normal Form): 2NF + no transitive dependencies.

Database Models

  • Hierarchical Model: Data organized in tree structure. Parent-child relationships.
  • Network Model: More flexible than hierarchical. Records can have multiple parent/child relationships.
  • Relational Model: Uses tables to represent data. Most common model today.
  • Object-Oriented Model: Stores data in form of objects, as used in programming languages like Java or Python.

Types of Database Models

Hierarchical Model

The hierarchical database model organizes data in a tree-like structure where each record has a single parent and possibly many children. This model is efficient for applications with a clear hierarchy, like file systems or organizational charts. It uses parent-child relationships to represent data, ensuring fast access but limited flexibility when handling complex relationships.

Network Model

This model allows each record to have multiple parent and child records, forming a graph structure. It's more flexible than the hierarchical model and is useful when relationships between data are many-to-many. However, managing pointers and relationships in the network model can be complex.

Relational Model

The relational model organizes data into tables (relations), where each table consists of rows (tuples) and columns (attributes). It is the most widely used model in modern databases due to its simplicity, flexibility, and the power of SQL for querying data. Relationships are maintained through primary and foreign keys.

Entity-Relationship (ER) Model

The ER model is a high-level conceptual data model that represents data in terms of entities (objects), attributes (properties), and relationships (connections between entities). It's primarily used during database design and later transformed into a relational model for implementation.

Integrity Constraints and Types

Domain Constraint

This ensures that the values of an attribute fall within a specified set of values or domain. For example, a column "age" should only contain numeric values within a certain range.

Entity Integrity

It ensures that each row in a table has a unique and non-null primary key. This guarantees the uniqueness of records.

Referential Integrity

This ensures that a foreign key in one table matches a primary key in another table, preserving consistency between related tables.

Keys

  • Primary Key: Uniquely identifies a record in a table.
  • Foreign Key: Refers to a primary key in another table, establishing a relationship.
  • Candidate Key: A column (or set of columns) that can qualify as a primary key.
  • Super Key: A set of one or more attributes that, taken collectively, uniquely identifies a record.

Normalization

Introduction

Normalization is the process of organizing data in a database to minimize redundancy and improve data integrity. It involves dividing large tables into smaller, related ones and defining relationships between them.

Normal Forms

  • 1NF (First Normal Form): Ensures that all columns contain atomic values, and each record is unique.
  • 2NF (Second Normal Form): Achieved when the table is in 1NF and all non-key attributes are fully functionally dependent on the primary key.
  • 3NF (Third Normal Form): Achieved when the table is in 2NF and all attributes are only dependent on the primary key (i.e., no transitive dependency).

Advantages

  • Reduces data redundancy
  • Improves data integrity
  • Makes data easier to maintain
  • Enhances query performance for normalized structures

Disadvantages

  • Can make queries more complex due to the need for joins
  • May impact performance in read-heavy systems
  • Denormalization might be needed for optimization in specific cases

Centralized and Distributed Database

Introduction

A centralized database stores all data at a single location, typically on one server.

A distributed database stores data across multiple locations, which may be on different computers or networks.

Advantages

  • Centralized Database:
    • Easier to manage and maintain
    • Better data integrity and consistency
  • Distributed Database:
    • Improved reliability and availability
    • Faster access for distributed users
    • Local autonomy of data

Disadvantages

  • Centralized Database:
    • Single point of failure
    • Poor scalability for large organizations
  • Distributed Database:
    • More complex to manage
    • Issues with data synchronization and consistency

Database Security

Introduction

Database security involves protecting the database from unauthorized access, misuse, or breaches, ensuring that data remains confidential, available, and integral.

Challenges

  • Unauthorized access or insider threats
  • SQL injection and other cyber attacks
  • Ensuring secure data transmission
  • Managing privileges and roles properly

Security Measures

  • User authentication and authorization
  • Data encryption (at rest and in transit)
  • Access control policies
  • Regular backups and audits
  • Firewalls and intrusion detection systems

Roles of DBA (Database Administrator)

  • Managing user access and permissions
  • Installing and upgrading database software
  • Backup and recovery
  • Performance tuning
  • Ensuring security policies are enforced

Practical Topics: DDL and DML Languages

DDL (Data Definition Language)

Used to define or modify the structure of database objects such as tables, schemas, and indexes.

Examples: CREATE, ALTER, DROP, TRUNCATE

DML (Data Manipulation Language)

Used to manage data within schema objects.

Examples: SELECT, INSERT, UPDATE, DELETE

SQL Data Types

Character and Binary Types

  • CHAR(n): Fixed-length character string. Padded with spaces if shorter.
  • VARCHAR(n): Variable-length character string. More space-efficient than CHAR.
  • BINARY(n): Fixed-length binary data.
  • VARBINARY(n): Variable-length binary data.

Text and Blob Types

  • TINYBLOB: Very small binary object (max 255 bytes).
  • TINYTEXT: Very small text field (max 255 characters).
  • TEXT: Long text string (up to 65,535 characters).
  • LONGTEXT: Very large text field (up to 4 GB).

Special String Type

  • ENUM: A string object with a predefined set of possible values.
  • BIT: A bit-field type for storing binary values.

Numeric Types

  • TINYINT: Very small integer (-128 to 127 or 0 to 255).
  • BOOLEAN: Stores TRUE or FALSE (internally stored as TINYINT 1 or 0).
  • INTEGER / INT: Standard integer (commonly up to ±2 billion).
  • FLOAT: Approximate numeric type with single precision.
  • DOUBLE: Double-precision floating point.
  • DECIMAL(p,s): Exact numeric value with precision (p) and scale (s).

Date and Time Types

  • DATE: Stores dates (YYYY-MM-DD).
  • DATETIME: Stores date and time (YYYY-MM-DD HH:MM:SS).
